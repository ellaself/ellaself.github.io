My foundational languages are Java and C/C++. To be candid, I have not coded in over a year. In other words, the last time that I took an ICS class was back in 2024. If you'll bear with me, let me see what I can remember from my previous courses, and I will tell you my thoughts.

Let’s compare:

When looking at the surface, both Java and TypeScript have the same inner workings. The most obvious comparison is that both are object-oriented programs. Throughout the modules and lessons, I found that topics like their encapsulation and data structures functions were essentially the same. Be it that their execution was a bit different. But the same principles of inheritance and dynamic programming apply to both. With implementations of generics and interfaces being nearly identical.

Not only that, but both Java and TypeScript are strongly typed. Although between the two, I believe that Java is a bit more strict. Being that TypeScript is a superset of JavaScript, it is a bit more flexible. Additionally, in TypeScript, you can turn on and off the dynamic type functionality. Which… I don’t believe Java has ever allowed me to do. Though when considering editors, I believe that TypeScript is the one to go with. I am an avid VScode user and cannot recommend it enough. I believe that this has to do with TypeScript being a more modern language and a subsidiary of Microsoft. Whereas Java, being a comparatively older language, has text editors like JGRASP. I don't think I need to explain anything more than that… if you know, you know! Additionally, I think that C is much more similar to TypeScript formatting-wise, at least compared to Java.

Final thoughts:

As for TypeScript as a standalone language, I think the language is straightforward. What is nice about the language is that many of the naming conventions for functions, objects, and elements outline what you want to do. For instance, if you want to create a constructor, then you would write constructor() { …}. Or, if you’d like to create a function, you would do function name (){ …. }. All together, making it much easier to read and easier to follow other programmers' logic.

Moreover, I think that the ES6 functions will save time, especially on WODs. With instances like arrow functions or destructors helping to shorten the code. Additionally, due to the declaration of types throughout the code, you are much more aware of the simple mistakes that you make as you code. Revealing how you input incompatible types or are lacking a proper return value.

As for athletic software engineering and practice WOD, I think they will be beneficial. I feel that it is a bit early to give my definite answer. However, I will say that I am getting a lot of practice in. From this, I can already see the improvement in my understanding of TypeScript and my ability to read code. That being said, I look forward to what is to come.
